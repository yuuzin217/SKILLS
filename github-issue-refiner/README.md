# github-issue-refiner

既存の GitHub Issue を最新の実装状況に合わせて調査・更新し、情報を保護しながら標準フォーマットへ整理するスキルです。

## 主な機能

- 単一 Issue の内容更新とフォーマット統一
- 指定された複数 Issue の一括調査・更新
- 実装・PR・テスト等の根拠に基づく進捗と完了条件の確認
- 更新前後の再取得による競合検出と差分検証
- `UPDATE`、`NO_CHANGE`、`REVIEW_REQUIRED`、`BLOCKED` の分類と結果集計

## 使う場面

- 既存 Issue を最新の実装状況に合わせて更新したい
- 既存 Issue を標準フォーマットに整えたい
- 指定した Issue 群を調査し、更新が必要なものだけ整備したい

新しい Issue の作成、要件からの起票、作業の Issue 分割には `github-issue-creator` を使用します。

## 更新モード

- **内容更新:** 最新の実装・設計根拠を確認し、古い前提や未完了事項だけを修正
- **フォーマット統一:** 情報と進捗を保ちながら、対象リポジトリの必須形式または9見出しに整理
- **一括更新:** 指定されたIssue群を分類し、`UPDATE` のみを小さな単位で更新

## 使い方

```text
Issue #123を最新の実装状況に合わせて更新して。対象: owner/repository
```

```text
Issue #123を標準フォーマットに統一して。既存情報とチェック状態は保持して。
```

```text
Issue #10〜#20を調査して、更新が必要なものだけ整理して。対象: owner/repository
```

```text
このリポジトリのOPEN Issueをすべて調査し、更新が必要なものだけ更新して。
```

```text
Issue #123の改善案を出して。まだGitHubには反映しないで。
```

## GitHubへの書き込み

相談・調査・改善案・下書きでは書き込みません。明示的な更新依頼と対象範囲の特定がある場合に限り、その範囲内の本文を更新します。明示された一括更新では、各Issueの再承認を求めず、安全に更新できる項目だけ処理します。

タイトル、ラベル、担当者、マイルストーン、Issueの状態や所属リポジトリの変更は、それぞれ明示的な指示が必要です。Issueのクローズ、再オープン、削除、新規作成、コメントの編集・削除は通常の整理に含みません。

## テンプレートと制約

- 対象リポジトリに必須Issueテンプレートがあれば、その必須項目を優先します。
- 標準テンプレートはSKILLSパッケージ内の `github-issue-creator/references/issue-template.md` を正本として共有します。
- refiner単体で使い、正本が見つからない場合は、SKILL.md内の9見出しをフォールバックとして使います。別テンプレートファイルは作りません。
- 既存情報、チェック状態、Issue本文以外のメタデータを不用意に失わないよう、更新直前と更新後にIssueを取得して確認します。
- `setup-global-skills.sh` は各スキルをディレクトリ単位で登録します。creatorとrefinerを別々に登録した場合でも、正本が利用できないときはフォールバックで動作します。
