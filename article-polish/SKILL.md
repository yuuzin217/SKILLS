# article-polish — 繋がりを保ち、盛りすぎない文章にする

脱力ちゃんの記事レビューで実際に繰り返し出た指摘を規則化したもの。
出典は 2026-11-26 の note 記事（Lauren Tan 講演4本まとめ）の推敲セッション。
汎用の美文規則ではなく、この書き手の実地の指摘に基づく。

## 柱1：前段との繋がりを切らさない

1. **節の頭に橋渡しの一文を置く** — 新しい節は、前の節を受けて始める。
   「では、その〜は」「その一番上が〜です」「設計で防ぎきれなかったものは、レビューに残ります」のように、
   前の話の何を受けているかを示してから本題に入る。いきなり新しい話題から始めない。
2. **冒頭の順序を逆行させない** — きっかけ → 対象 → この記事でやること、の順に流す。
   サブタイトル等で結論を先に言い切ってから本文で経緯に戻ると、読み手は逆行を感じる。
3. **浮いた単文に居場所を作る** — 前後と繋がらない単独の文は放置しない。
   リストの導入文にする（「中でも印象的だったのが、この2つの禁止です。」）、
   前後の段落に吸収する、のどちらかで処理する。

## 柱2：コンパクトに保ち、盛りすぎない

1. **長い説明は圧縮する** — 同じ内容を言い換えて繰り返さない。段落単位で
   「この段落がないと何が失われるか」を問い、答えが弱ければ削るか短くする。
2. **重複する要約行は消す** — サブタイトルや要約行が本文冒頭と同内容なら、どちらか一方にする。
   基本は本文に残し、飾りの要約行を消す。
3. **情報を全部並べない** — 数字や事例は列挙より「並び順」で意味を持たせる
   （例：成果の数字より先に先行投資の数字を置く）。盛るほど主張がぼやける。

## 細部の規則

- **文体を統一する** — 本文が です・ます調なら、サブタイトル・見出し回りの文も揃える。
  常体の一文だけが混ざると浮く。
- **見出しは本文への約束** — 見出しが言い切る範囲と本文の中身を一致させる。
  ずれたら本文ではなく見出しの方を実態に合わせて直す（例：「割り引いて読むところ」→「そのまま真似できない前提」）。
- **専門用語には初出で短い注釈** — 括弧で一言（例：スキャフォールド（決まった雛形を自動で用意する仕組み））。
  注釈は短く、本文の流れを止めない長さにする。
- **主語を落としすぎない** — 主語のない断片文は、読み手に補完を強いる。
  「〜と呼ばれ、アンチパターンとされていました」のように、誰が・何がを文として完結させる。

## 主張と出典の扱い

- **主張の帰属を明示する** — 数字や事例は「誰の自己申告か」「どの出典の主張か」を本文か断り書きで示す。
  検証されていない数字を事実として書かない。
- **二次情報源は きっかけ と出典に留める** — SNS 投稿などの二次情報は、冒頭のきっかけと参考リストに置く。
  本文の主張は一次情報（講演・公式資料）に帰属させる。

## レビューの進め方（書き手とレビュアーの作業規則）

1. **指摘を受けている間は直さない** — レビュー中は、説明と修正案だけを返し、
   採用された案は番号つきの保留リストに貯める。
2. **反映は一括で** — ユーザーが「全部終わった」と言ってから、保留リストを一括で反映する。
   途中で1件ずつ直すと、全体の繋がり（柱1）を見失う。
3. **校正の完了は件数で言う** — 誤字・表記の修正は目視で「直った」と言わない。
   文字列検索の件数（誤表記 0 件／正表記 N 件）を証拠にする。
   小さい ャュョ を含むカタカナ語、英字混じりの語は重点的に検索する
   （実例：「スキャフォールド」が「スカャフォールド」になっていた）。

## 適用範囲

- 対象：この書き手の日本語記事の下書き・推敲・レビュー対応。
