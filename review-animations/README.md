# review-animations

アニメーション・モーションコードを高い品質基準でレビューするスキルです。

## 概要

Emil Kowalski のデザインエンジニアリング哲学に基づき、アニメーションコードを厳格にレビューします。デフォルトは指摘モード — 承認は獲得しなければなりません。一般コードのレビューは対象外です。

## いつ使うか

- PR のアニメーション変更をレビューしたい
- モーションコードの品質をチェックしたい
- `ease-in` や `scale(0)` などの問題を検出したい

## 使い方

### 1. スキルの有効化

Cursor のスキル設定で `review-animations/` ディレクトリをスキルとして登録します。

### 2. プロンプト例

```
この diff のアニメーション変更をレビューして。
```

```
このコンポーネントの transition 設定をチェックして。
```

```
モーションコードに問題がないか、review-animations の基準で見て。
```

### 3. レビュー基準（10 の非交渉ルール）

1. **正当化されたモーション** — 「なぜアニメートするか」に答えがあるか
2. **頻度に適したモーション** — キーボード操作・100回/日以上はアニメーションなし
3. **レスポンシブなイージング** — enter/exit は `ease-out`、UI での `ease-in` はブロック
4. **300ms 以下** — UI アニメーションは 300ms 以内
5. **起点と物理的正しさ** — ポップオーバーはトリガーから拡大、`scale(0)` 禁止
6. **割り込み可能性** — トースト・トグルは割り込み可能であること
7. **GPU のみ** — `transform` と `opacity` のみアニメート
8. **アクセシビリティ** — `prefers-reduced-motion` と hover ゲーティング
9. **非対称な enter/exit** — 意図的な操作は遅く、システム応答は素早く
10. **一貫性** — プロダクトの個性に合ったモーション

### 4. 出力形式

**Part 1 — 発見事項テーブル（必須）**

| Before | After | Why |
|--------|-------|-----|
| 問題のあるコード | 修正案 | 理由 |

**Part 2 — 判定（必須）**

- **Block** — 致命的なモーション問題あり
- **Approve** — 問題なし

### 5. 即座にフラグすべきパターン

- `transition: all`
- `scale(0)` や純粋フェードのみの entrance
- UI での `ease-in`
- キーボードショートカットや高頻度操作でのアニメーション
- 300ms 超の UI duration
- レイアウトプロパティのアニメーション
