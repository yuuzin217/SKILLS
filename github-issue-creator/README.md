# github-issue-creator

要件をリポジトリの現状に基づく、簡潔で実装可能な GitHub Issue にまとめるスキルです。

## 主な機能

- 関連コード、ドキュメント、既存 Issue・PR を調査し、実装状況と重複を確認
- 目的、対象範囲、実装方針、作業順序、完了条件を整理
- Feature、Bug、Refactoring、Security、Infrastructure、Documentation に対応
- 相談や下書き依頼では提案のみを返し、明示的な依頼がある場合だけ Issue を作成・更新
- 作成・更新後に Issue を再取得して内容を検証

## 使う場面

- GitHub Issue を作成・起票したい
- 要件や開発計画を Issue にまとめたい
- 開発作業を適切な粒度の Issue に分割したい
- 既存 Issue との重複や実装状況を確認して整理したい

## 使い方

スキルを利用できるエージェント環境に `github-issue-creator/` を登録し、対象リポジトリと要件を指定します。

```text
この機能を GitHub Issue にして。対象: owner/repository
```

```text
既存実装を調査して、未実装部分を Issue 案にまとめて。まだ起票しないで。
```

```text
この要件を適切な粒度に分割して、重複を確認したうえで Issue を作成して。
```

```text
既存 Issue #123 を更新して。完了条件に互換性の確認を追加して。
```

## GitHub への書き込み

GitHub への Issue 作成は、ユーザーが作成・起票・登録を明確に依頼した場合に限ります。相談、調査、提案、下書き、または起票しない旨の指定では書き込みません。既存 Issue の更新には、明示的な更新依頼と対象 Issue の特定が必要です。

調査には対象リポジトリのコード・ドキュメント・Issue・PRを読む権限が必要です。作成・更新時は、利用する GitHub CLI または連携ツールに対象リポジトリの Issues 書き込み権限が必要です。ラベルやマイルストーンは、既存の設定を確認して適切なものだけを使います。

## ディレクトリ構成

```text
github-issue-creator/
├── SKILL.md
├── README.md
└── references/
    └── issue-template.md
```

## 制約

- 対象リポジトリを特定できない場合、特定のリポジトリを暗黙の起票先にしません。
- 既存 Issue が要件を満たす場合は重複作成しません。
- 確認できない仕様や優先順位を事実として補いません。
- Security の詳細は対象リポジトリの脆弱性報告手順に従い、公開 Issue に機密性のある情報を記載しません。
- Issue の作成・更新以外のリポジトリ設定変更、PR マージ、リリース、デプロイは行いません。
